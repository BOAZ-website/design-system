# 문체와 문구 (voice-and-tone)

> 표기 규칙은 `components/_template.md` 상단 "표기 규칙"과 같음. 패턴은 여러 컴포넌트에 걸친 사용 규칙이라 값보다 "언제·어떻게"를 적음

## 1. 개요

- 목적: 사용자에게 보이는 문구(안내·오류·버튼·FAQ)의 문체와 구조를 한 곳에 정함
- 적용 범위: 공개 웹사이트(frontend)의 모달·입력 오류·버튼·링크·FAQ 문구
- 범위 밖: 관리자 콘솔 문구(6절), 약관·개인정보 처리방침 같은 법적 문서 본문, 백엔드 오류 메시지 원문
- 관련 명세
  - `components/modal.md` 3절(7종 문구)
  - `components/button.md` 3절·5절·8절(버튼 종류, pending 라벨 유지)
  - `components/text-field.md` 8절(입력 필드 아래 오류 문구)
  - `components/checkbox.md` 5절(전문 보기·접기)
  - `patterns/feedback.md`(오류를 모달로 띄울지 필드 아래에 둘지의 판단)

## 2. 규칙

### 2.1 PATTERN-04-01 문체

| 상황 | 규칙 | 근거 |
| --- | --- | --- |
| 안내·결과 문장 | 합쇼체 평서문. 어미는 "입니다", "되었습니다", "없습니다" | Figma 4243:4452, Figma 4243:4480, Figma 5164:5542, Figma 5164:5587 |
| 요청 | 어미 "해주세요" 한 가지. "해주시길 바랍니다", "하시기 바랍니다" 사용 안 함 | Figma 4243:4492(위반 사례), Figma 5164:5587 |
| 권유 | 어미 "해보세요" | Figma 4243:4452, Figma 4243:4480 |
| 확인 질문(확인창) | 합쇼체 의문 어미 "하시겠습니까?" | 코드 `src/pages/apply-page.tsx` |
| FAQ 질문 | 지원자 목소리 해요체 의문 어미 "나요?" | 코드 `src/pages/curriculum-page.tsx` |
| 부호 | 문장 끝은 마침표. 느낌표 사용 안 함 | Figma 4243:4452, Figma 5164:5621 |
| 지칭 | 사용자는 지칭하지 않음. 동아리는 "BOAZ" | Figma 5164:5542 |

- 문체 예외: 해요체 종결("알려드릴게요")은 안내·결과 문장에 쓰지 않음
  - 현재 사례 `alert` 문구 "신청이 완료되었습니다! 모집 시작 시 이메일로 알려드릴게요."
  - 고친 문구 "신청이 완료되었습니다. 모집이 시작되면 이메일로 알려드리겠습니다."
  - 한 문장 안에서 합쇼체와 해요체를 섞지 않음
- 해요체가 허용되는 곳은 FAQ 질문뿐임. 질문은 지원자가 묻는 말이고, 답변은 합쇼체
- FAQ 질문 실제 문구는 API 데이터임. Figma 시안의 질문은 "코딩테스트를 보나요?", "트랙 간 중복 지원이 가능한가요?", "경쟁률은 어느 정도 인가요?"로 모두 해요체 의문 어미(2026-10-22 확인)

### 2.2 맞춤법: "해주세요" 붙여쓰기 통일

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| 보조 용언 "주다"·"보다" | 앞말에 붙여 씀: "입력해주세요", "기다려주세요", "신청해보세요" | 한글 맞춤법 제47항(보조 용언은 띄어 씀이 원칙이나 붙여 씀도 허용), Figma 4243:4492, Figma 5164:5587 |
| "다시 한 번" | 띄어 씀(명사 "번") | Figma 4243:4504, Figma 5164:5621 |
| 존칭 "해주셔서" | 붙여 씀 | Figma 5164:5542 |

- 붙여쓰기 선택 근거
  - Figma 모달 7종이 모두 붙여쓰기. Figma 전체에서도 "주세요" 문구 163곳 중 붙여쓰기 150곳, 띄어쓰기 13곳(지원 폼 안내 문구 등)으로 붙여쓰기가 다수(2026-10-22 확인)
  - 티켓 PATTERN-04-01이 "해주세요"로 표기
  - frontend도 붙여쓰기가 다수(사전 알림·입력 오류 문구). 띄어쓰기는 5곳(6절)
- 띄어쓰기도 맞춤법상 올바른 표기라 틀린 표기가 아님. 통일이 목적이며 한쪽만 허용함
- 붙여쓰기를 기준으로 삼아 띄어쓰기 5곳을 고침(6절)

### 2.3 PATTERN-04-02 오류 문구 2문장 구조

| 순서 | 내용 | 규칙 |
| --- | --- | --- |
| 1문장 | 무엇이 잘못됐는지 | 사실만 적음. 합쇼체 평서문. 책임을 사용자에게 돌리는 표현 사용 안 함 |
| 2문장 | 다음 행동 | 사용자가 할 일 하나. 어미 "해주세요". 대상과 방법이 드러나야 함 |

- 1문장에 요청을 쓰지 않음. 2문장에 "다시 한 번 확인" 같은 대상 없는 요청을 쓰지 않음
- 원인을 모를 때(서버 실패)는 1문장에 결과만 적고, 2문장에 재시도 행동을 적음
- 입력 형식 오류는 모달이 아니라 입력 필드 아래 문구가 우선(`components/modal.md` 8절). 같은 2문장 구조를 한 줄로 합쳐 씀

## 5. Do / Don't

| Do | Don't |
| --- | --- |
| 1문장에 잘못된 점, 2문장에 할 일 | 1문장과 2문장에 같은 요청 반복 |
| "이메일을 다시 입력해주세요." | "이메일을 다시 입력해주시길 바랍니다." |
| "다른 이메일을 입력해주세요." | "다시 한 번 확인해주세요."(대상 불명) |
| 안내·결과는 합쇼체: "알려드리겠습니다." | 해요체 혼용: "알려드릴게요." |
| 마침표로 끝냄 | 느낌표 |
| "해주세요"·"해보세요" 붙여쓰기 | 같은 화면에서 "해 주세요"와 "해주세요" 혼용 |
| 동작 버튼은 "제출하기" | "제출", "제출 버튼" |
| 진행 중에도 라벨 유지 | 라벨을 "신청 중"으로 교체 |
